CVS / ACCOUNTS PAYABLE AUTOMATION

Invoice data that survives validation.

01

File intake

The user uploads an invoice. The application detects the file and stops unsupported file types before extraction begins.

02

Gemini document parsing

The Google Gemini API extracts the invoice ID, vendor name, vendor number, line items, UPC values, dates, and totals. It returns the result as structured JSON.

03

Data transformation

The transformer separates line item entities, creates a stable summary, and prepares UPC values for Snowflake. When a UPC ends in zero, the workflow removes that final digit to match the stored format.

04

Snowflake validation

The integration confirms that the vendor number exists, checks for duplicate invoices, validates the invoice date range, compares total amounts, and stores the validated record.

05

Generated outputs

The final step produces line item CSV files, structured JSON, and Excel workbooks for audit and analysis.

06

Operational result

The Accounts Payable team can review every invoice with fewer manual entry errors and spend more time investigating exceptions.

UMD / TERP TRACKER

Home and away performance, queried from the same schema.

01

Management question

The project examined how Maryland performed in home, away, and neutral games so team management could compare opponents, venues, players, and coaches.

02

Database design

Built a relational schema connecting matches, players, coaches, and venues. SQL queries calculated wins, losses, win ratios, and batting averages by location.

03

Opponent result

Penn State ranked first in the opponent analysis with 10 Maryland wins across 20 matchups. Iowa recorded six wins across ten matchups.

04

Venue result

The venue query isolated away and neutral locations where Maryland lost most often, led by Palm Springs and followed by Boca Raton.

05

Decision use

The analysis gives team management a structured way to compare location effects and review player or coach performance before planning future matchups.

UMD / MUSIC RECOMMENDATION SYSTEM

Recommendations shaped by sound and context.

01

Product goal

Tailored song suggestions to a listener’s preferences, mood, weather, and time of day using Spotify track data.

02

Data preparation

Filled missing values, removed unused fields, and normalized audio features including energy, loudness, valence, danceability, and tempo.

03

Two recommendation paths

Used context rules to filter eligible songs and K nearest neighbors to retrieve tracks with similar normalized audio characteristics.

04

Model decision

Selected KNN for its simplicity and lower memory requirements. The original presentation did not report a validated accuracy score, so the project makes no unsupported performance claim.
